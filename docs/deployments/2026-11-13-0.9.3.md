# Version 0.9.3 consistency prefill

Version 0.9.3 continues the archived 0.9.2 source with the requested manual
consistency-check workflow. **Auto-fill content** follows **Copy wikitext**
and opens a new Wikipedia source-editor tab at section zero. The
`aranami-check-job` parameter selects an already prepared Toolforge proposal;
the Tampermonkey script reads it, verifies the page and original source, fills
the full lead and summary, and invokes native Preview. The editor saves the edit.
The updated userscript explicitly binds `const mw = window.mw` and retains its
Tampermonkey page-window fallback.

Article history placement uses verified Chinese template roots and redirects,
including mixed simplified/traditional names. Acquisition retains the insertion
boundary after active nominations and introductory notices, before project
banners and later banners. The updater preserves unrelated source and withholds
ambiguous layouts. A new source identity regenerates cached repair plans.

Checks now paginate history directly with Previous and Next controls and
continuous numbering. Talk-page links appear once beside each article title.
Complete prepared proposals are retained in a separate bounded Parquet result,
independent of the shared dashboard capacity. Its sixteen MiB bound covers
complete findings and proposals while the dashboard remains bounded at eight
MiB. The input limit supports 2,048 proposals and four MiB of source facts. HTTP reads require the saved check
generation to match; missing or stale proposals retain the compact fallback.

The existing memory-display correction is included in this same release. The
Memory value subtracts inactive filesystem cache from cgroup usage while keeping
active pages and the existing allocation. Missing counters remain unknown.
